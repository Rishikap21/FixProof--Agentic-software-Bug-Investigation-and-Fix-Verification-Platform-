# FixProof

FixProof is an AI-powered bug investigation, patch generation and automated fix verification platform designed to help developers identify, understand and validate software fixes.

## Features

- Project upload using ZIP files
- Bug report submission
- ML-based issue classification
- AI-powered root cause analysis
- Automated patch generation using Google Gemini
- Human patch review and approval
- Isolated Docker-based test verification
- Verification reports
- MySQL database integration
- Protection of original project source code

## Technology Stack

- **Frontend:** HTML, CSS, JavaScript
- **Backend:** Python, FastAPI
- **Database:** MySQL, SQLAlchemy, PyMySQL
- **Artificial Intelligence:** Google Gemini, LangGraph
- **Machine Learning:** Scikit-learn, Pandas, Joblib
- **Verification:** Docker, Pytest, Git

## Prerequisites

- Python 3.13 (tested locally)
- Git
- MySQL Server
- Docker Desktop
- Valid Google Gemini API key

## Installation and Setup

### 1. Create a virtual environment

```powershell
python -m venv .venv
```

### 2. Activate the virtual environment

```powershell
.\.venv\Scripts\Activate.ps1
```

### 3. Install dependencies

```powershell
pip install -r requirements.txt
```

### 4. Create the MySQL database

```sql
CREATE DATABASE IF NOT EXISTS fixproof_db;
```

### 5. Configure environment variables

```powershell
Copy-Item .env.example .env
```

Update the `.env` file with your MySQL credentials and Gemini API key.

```env
DB_USER=root
DB_PASSWORD=your_mysql_password
DB_HOST=localhost
DB_PORT=3306
DB_NAME=fixproof_db
GEMINI_API_KEY=your_gemini_api_key
GEMINI_MODEL=gemini-3.5-flash-lite
```

Never commit your actual `.env` file or credentials to GitHub.

For an optional local SQLite demo, configure:

```env
DATABASE_URL=sqlite:///./fixproof.db
```

### 6. Build the Docker verification image

Start Docker Desktop and run:

```powershell
docker build -f Dockerfile.verifier -t fixproof-verifier .
```

### 7. Start FixProof

```powershell
python -m uvicorn backend.main:app --reload
```

Open the application:

- Application: http://127.0.0.1:8000/
- API documentation: http://127.0.0.1:8000/docs

## Application Workflow

1. Upload a Python project as a ZIP file.
2. Submit a bug report.
3. Select the uploaded project.
4. Perform AI-powered bug investigation.
5. Review the generated root cause analysis.
6. Generate and review the proposed patch.
7. Approve the patch.
8. Verify the fix using Docker and Pytest.
9. View the verification report.

## Machine Learning

FixProof uses TF-IDF and Logistic Regression for issue classification.

The issue classification categories are:

- Bug
- Feature
- Question

The original NLBSE dataset is excluded from the repository because redistribution permissions have not been confirmed.

To retrain the issue classification models, obtain the original dataset with appropriate permissions and place the required files at:

```text
ml/nlbse_dataset/data/issues_train.csv
ml/nlbse_dataset/data/issues_test.csv
```

Run:

```powershell
python ml/train_model.py
```

This generates the general issue classification model, repository-specific models and evaluation reports.

The legacy classifier requires a separate `ml/model.pkl` artifact that is not generated by the current training script.

## Fix Verification

FixProof applies proposed patches to a temporary project copy and executes the supplied tests inside a restricted Docker container.

The original uploaded project remains unchanged.

The AI investigation, patch generation, MySQL integration and Docker verification workflow have been successfully tested locally using sample Python projects.

A successful verification report confirms that the supplied tests passed. It does not guarantee that every possible defect has been resolved.

## Security and Limitations

- FixProof is a local single-user academic prototype.
- Authentication is not currently implemented.
- Keep the application bound to localhost.
- Do not upload confidential source code or credentials without permission.
- Relevant source code may be sent to Gemini for analysis.
- Docker isolation reduces execution risks but is not a complete security boundary.
- The default verification image supports pytest and standard-library Python projects.
- Projects with additional dependencies may require a customized verification image.
- Verification fails when no tests are collected.
- AI-generated fixes require human review.
- ML model compatibility may require retraining.
- Do not run the legacy verification CLI on untrusted code.
- Older patches without project metadata must be regenerated.

## Project Objective

FixProof aims to reduce manual debugging effort by combining artificial intelligence, machine learning, human patch review and isolated automated software testing into a unified bug investigation and fix verification workflow.
